# AgentLoop — To-Be-Done

> **Purpose:** Single source of truth for the work required to take AgentLoop from a 2-star, 10-day-old prototype to a credible, mass-adopted "agents that actually finish" tool.
>
> **Audience:** The autonomous coding agent (Claude Code / OpenCode / Aider / Codex / Goose) that will execute this file.
>
> **How to use this file:**
> 1. Read it top-to-bottom before touching anything.
> 2. Work strictly in phase order. Do not skip ahead — later phases depend on earlier ones.
> 3. Check off `[ ]` → `[x]` as you complete each task.
> 4. Append a `### Notes` block under any task you couldn't fully complete, explaining what blocked you.
> 5. Commit after every task with `feat:` / `fix:` / `docs:` / `chore:` conventional commits.
> 6. Run `python3 test_oracle.py && python3 test_loop.py` after every code-touching task. Both must pass before you move on.
> 7. If a task references a file path that does not exist yet, create it.
> 8. Never break the `agentloop` CLI's existing public flags. Additive only.
> 9. Keep `agentloop` zero-runtime-dependency for the default install. Anything new that requires a dep goes in an optional extras group.
> 10. Do not edit this file's structure. Add notes; don't rewrite the plan.

## Phase 1 — Container Isolation (Day 2–3, ~1 day)

This is open issue #2. It is the single biggest blocker to production trust. Without it, no security team will approve AgentLoop for use on proprietary code.

### T1.1 — Implement `--docker` mode
- [x] **Why:** Currently the wrapped agent runs with `cwd=sandbox` but inherits host filesystem, network, and process access. This is unacceptable for untrusted agent harnesses.
- [ ] **Files:** new file `agentloop/docker.py`, modify `agentloop/__init__.py`
- [ ] **Action:**
  - Create `agentloop/docker.py` with a function `run_in_docker(cmd: str, sandbox: Path, env: dict, timeout: int) -> subprocess.CompletedProcess`.
  - The container must:
    - Mount only `sandbox/` as read-write at `/workspace` inside the container.
    - NOT mount the host's `~/.ssh`, `~/.aws`, `~/.config`, etc.
    - Run as a non-root user.
    - Network policy: `--network=none` by default; allow `--network=host` via `AGENTLOOP_DOCKER_NETWORK` env var for agents that need model API access (most do — document this clearly).
    - Auto-detect a base image: try `python:3.12-slim` first; fall back to whatever has the agent CLI installed.
    - Strip all secrets from the container env (reuse `safe_env()`).
  - Add `--docker` flag to `argparse` in `main()`.
  - In `run_cli_mode`, if `args.docker` is set, route through `run_in_docker` instead of `subprocess.run`.
- [ ] **Acceptance:**
  - `agentloop --docker "create a file called test.txt" --verify "test -f sandbox/test.txt"` works end-to-end on a host with Docker installed.
  - Inside the container, `env | grep -i key` returns nothing credential-like.
  - Inside the container, `ls /` shows no host home directory.
  - Outside the container, after the run, `sandbox/test.txt` exists.
- [ ] **Dependencies:** T0.5 (so the env-var rename is consistent).
- [ ] **Commit message:** `feat: --docker mode for hard sandbox isolation (closes #2)`

### T1.2 — Add a `--podman` alias

## Explicit Non-Goals

Things that would dilute focus. DO NOT do them during this 30-day window.

- **Do NOT build your own agent.** You're a wrapper. Stay a wrapper.
- **Do NOT build a hosted/SaaS version.** OSS-first; SaaS later if ever.
- **Do NOT add a GUI.** Web monitor is enough. TUI is fine. Native GUI is a trap.
- **Do NOT support non-coding agents** (no data analysis, no research agents). Out of scope.
- **Do NOT add fine-tuning / model hosting / RAG.** Not your layer.
- **Do NOT chase every new harness release.** Support the top 6 presets; let `AGENT_CMD` cover the long tail.
- **Do NOT add a plugin system.** Not yet. Premature.
- **Do NOT optimize for benchmarks by overfitting.** If the SWE-bench numbers look too good, audit the verifier. False greens are the very thing you exist to defeat.
